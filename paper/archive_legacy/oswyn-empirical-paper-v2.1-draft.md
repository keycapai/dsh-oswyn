## 摘要（Abstract）

在长程软件工程（SWE）与程序化工具调用（Programmatic Tool Calling, PTC）智能体会话中，目录扫描、源码读取与回归测试报错随步骤追加累积，使累计上行 Token 呈二次方级 $\mathcal{O}(T^2)$ 膨胀，并引发“大海捞针（Lost-in-the-Middle）”注意力稀释。现有的外部代理区间折叠方案（如 `billion-context`）不仅需要额外工具调用轮次，还会因改写历史消息中段而击穿大模型 KV-Cache 前缀缓存，并因粗粒度概括抹除早期关键常量与算术算子。

本文提出并实证评估了 **DSH-OSWYN（Only See What You Need，v2.1）**——一种直接构建于 `@deepseek-ai/dsh-session` 有向无环表面图（Surface DAG）之上的**零额外轮次步边界内联上下文微蒸馏系统**。OSWYN 允许智能体在生成当前动作的同时，通过内联 `dsh-result-summary` 与 `dsh-reply-summary` 围栏对上一步工具输出执行**前缀保留截断（`truncate keep N lines|chars`，从字节 0 保留前缀以 100% 保护 KV-Cache）**、**结构化事实替换（`replace`）**或**失败调用连同入参彻底丢弃（`discard`）**，辅以静默后台自动兜底（`runAllAutoPolicies`）、按需无损回溯工具（`tool_result_recall`）以及 v2.1 能力边界三重防护机制（公式算子逐字保留、跨步计算前主动回溯门控、终局合成轮免围栏推理豁免）。

我们在真实推理网关上跨越 5 款跨代际模型（`DeepSeek 4.1 Flash`、`Gemini 3.8 Flash`、`Kimi 3.1 Pro`、`Hunyuan 4`、`Gemini 4`）与原版 `billion-context@0.1.211` 开展了 4 项受控实验（累计 180+ 组真实多步会话），并严格采用 **`dsh-cost-meter` 核对的各模型官方实际 API 价格（含多步重复 KV-Cache 命中费用与额外输出 Token 费用）** 进行经济学核算。实证结果表明：
1. **上下文压缩率优势**：在 15 步连续 SWE 会话中，`OSWYN-Standard` 与 `OSWYN-PTC` 分别实现 **`72.66%`** 与 **`78.09%`** 的工具载荷净压缩率，第 15 步单步上行 Prompt 从 `21,445` 降至 **`9,868` tokens（`-53.98%`）**；旗舰模型在中高难度任务上自发达成 **`87.81%–94.54%`** 压缩率。
2. **能力与智力保持优势**：在 `B1`–`B11` 能力临界点基准（143 轮会话）中，v2.1 `OSWYN_V2_Optimized` 在前 9 题（`B1`–`B9`）取得 **`27/27`（`100.0%`）满分通过**，**反超无压缩标准基线（`26/27 = 96.3%`）`+3.7 pp`**；在全部 10 道可解题（`B1`–`B10`）取得 **`29/30`（`96.7%`）通过率**，**与无压缩基线（`29/30 = 96.7%`）100% 持平（零净智力损失）**；`B6` 与 `B9` 经 v2.1 插件调优后双双从 `66.7%` 跃升至 **`100.0%`**。相比之下，原版 `billion-context` 在 15 步会话中的终局常量召回率仅为 **`0/7`（`0.0%`）**（`OSWYN-Standard` 为 **`4/4 = 100.0%`**）。
3. **实际 API 成本优势与适用边界**：在 15 步连续会话中，`OSWYN-Standard` 累计总计费 Token 净减 **`-38.83%`**（未缓存 Fresh Input 净减 **`-5.20%`**，而 `billion-context` 因破坏缓存前缀导致 Fresh Input 暴增 **`+21.01%`**）；按实际 API 无缓存/跨节点计费净省 **`-28.10%`**（30 步/50 步净省 **`-45.41%` / `-52.23%`**），按 50% 缓存命中交互调试计费净省 **`-18.48%` 至 `-21.40%`**。同时，实证数据也揭示了超短会话（$\le 4$ 步且载荷 $<10\text{k}$ 字符）中因输出单价高达缓存命中输入 $50\times\text{–}200\times$ 而产生的“高价额外输出倒挂效应”，确立了 **会话步数 $T \ge 12\text{–}15$ 步** 或 **单任务载荷 $\ge 18\text{k}$ 字符** 的定量盈亏平衡准则。此外，`DeepSeek 4.1 Flash + OSWYN v2.1` 仅用 **`Gemini 4` 实际 API 费用的 `7.1%`（节省 `-92.9%` 跨代际成本）** 即在 `B1`–`B10` 上达到了与旗舰模型相当的解题准确率（`96.7%` vs `100.0%`）。

**关键词**：软件工程智能体（SWE Agents）；上下文微蒸馏（Context Micro-Distillation）；KV-Cache 前缀保护；程序化工具调用（PTC）；能力边界保持；API 计费经济学

## 1. 引言与核心结论先行（Introduction & Executive Summary）

### 1.1 研究背景与问题定义

在现代自治软件工程（SWE）智能体与程序化工具调用（Programmatic Tool Calling, PTC）工作流中，智能体通过多步循环执行目录扫描（`find/grep`）、源码阅读（`read`）、补丁修改（`edit`）与测试验证（`npm test`）。设会话总步数为 $T$，第 $k$ 步产生的工具输入输出与中间回复长度为 $L_k$。在传统追加式（Append-Only）上下文管理下，第 $k$ 步的瞬态历史载荷会在后续 $T-k$ 个步骤中被**反复重发、重复计费**：

$$\text{PromptTokens}_{\text{Append}}(T) = T \cdot L_{\text{sys}} + \sum_{k=1}^{T} (T - k + 1) \cdot L_k = \mathcal{O}(T^2)$$

这种二次方级膨胀带来三重严峻挑战：
1. **注意力稀释与“大海捞针”退化（Lost-in-the-Middle）**：大量早已失效的错误堆栈、冗长通过日志与同名影子配置（Shadowed Constants）堆积在上下文中，干扰模型对当前活跃状态与算术逻辑的精确追踪。
2. **外部代理压缩的“KV-Cache 击穿税”与细节抹除**：以 `billion-context`（`bili`）为代表的外部代理方案通过注入 `acp_status` / `compress` 工具，在达到阈值时将历史消息区间 $[s_{\text{start}}, s_{\text{end}}]$ 折叠为一段概括文本。然而，改写早期消息序列的中段会直接改变后续所有 Token 的前缀哈希，导致原本享受 $90\%\text{–}98\%$ 折扣的 **KV-Cache 缓存命中输入（`cacheHit`）退化为全价未命中新鲜输入（`cacheMiss`）**，且粗粒度区间概括极易丢失精确常量与位运算算子。
3. **内联压缩的“额外输出单价不对称悖论”**：在主流大模型官方 API 定价中，**生成输出 Token（`output`）的单价是未缓存输入（`cacheMiss`）的 $3\times\text{–}5\times$，更是缓存命中输入（`cacheHit`）的 $50\times\text{–}200\times$**（例如 `DeepSeek 4.1 Flash` 官方谷价中 `cacheHit = ¥0.02/M`，而 `output = ¥4.00/M`，相差 **200 倍**）。若压缩机制要求模型输出冗长的摘要围栏，在短会话中额外输出的费用可能超过其省下的缓存输入费用。

### 1.3 基于实测数据的方法优点（Advantages）与不足（Limitations）全面剖析

科学严谨的工程评估必须同时呈现方法的优势与客观边界。以下完全依据实验一至实验四的真实测量数据，归纳本方法的 **4 项核心优点** 与 **5 项客观不足**：

#### 一、实测验证的核心优点（Empirical Advantages）

1. **高压缩率与 KV-Cache 前缀局部性兼得，消除外部代理方案的“缓存击穿税”**：
   - 在 Exp 1 的 15 步连续会话中，`OSWYN-Standard` 与 `OSWYN-PTC` 将常驻工具载荷分别从 `57,147` 字符压缩至 **`15,624` 字符（`-72.66%`）** 与 **`12,794` 字符（`-78.09%`）**。
   - 更关键的是，由于 OSWYN 仅在步边界对**紧邻上一步**工具结果执行原位替换或从字节 0 开始的前缀截断（`truncate keep N lines`），绝不改写早期历史前缀，其 15 步累计未命中缓存的全价输入（`cacheMiss`）仅为 **`40,297` tokens（比不压缩基线的 `42,507` tokens 还少 `-5.20%`）**。相反，原版 `billion-context@0.1.211` 因中途折叠改写历史消息序列，导致 `cacheMiss` 全价 Token 激增至 **`51,439` tokens（比不压缩基线恶化 `+21.01%`）**。在 `DeepSeek 4.1 Flash` 官方定价中，`cacheMiss`（`¥1.00/M`）比 `cacheHit`（`¥0.02/M`）贵 **50 倍**，`billion-context` 仅因破坏缓存前缀就多付了 `+21.01%` 的全价输入税。
2. **能力临界点“零净智力损失”，并在强噪声多步追踪任务上反超无压缩基线**：
   - 在 Exp 4 的 11 道能力临界点题中，经 v2.1 优化的 `OSWYN_V2_Optimized` 在 `B1`–`B9`（27 轮）上达成 **`27/27`（`100.0%`）**（无压缩基线为 `26/27 = 96.3%`），在 `B1`–`B10`（30 轮可解题）上达成 **`29/30`（`96.7%`）**（与无压缩基线 `29/30 = 96.7%` 完全持平）。
   - 在 `B1_VM_Bytecode_Trace`（4 步 16 位虚拟机状态追踪）中，无压缩基线因 130 行历史废操作码干扰出现 `1/3` 轮次算错（`66.7%`），而 OSWYN 各组凭借步间摘要构成的“结构化外部工作记忆（External Scratchpad）”，在全部 **9/9 轮测试中 100% 算对精确解 `197`**。
3. **支持按需无损回溯（`tool_result_recall`），100% 攻克有损压缩的“延迟绑定陷阱”**：
   - 在 `B7_Late_Bound_Key_Slot`（Step 2 报错突然索取 Step 1 被替换丢弃的 `SBOX_SLOT_27/31`）与 `B10_MultiReg_Bitwise_Pipeline`（Step 3 需重跑 Step 1 的 4 行位运算函数）中，不带回溯的 `OSWYN_Standard` 通过率从 `100%` 暴跌至 **`16.7%`（`1/6`）**；而挂载 `tool_result_recall` 后，模型在 **100% 的轮次中自主调用回溯取回原文，将通过率恢复至 `100.0%`（`6/6`）**。
4. **对长程会话与高冗余推理模型（如 `Hunyuan 4` / `Gemini 4`）带来显著的实际 API 账单缩减**：
   - 在 `Hunyuan 4`（官方价 `$0.042 / $0.834 / $2.501` per 1M）上，单步 Nudge 不仅引导模型将失败调用从 `truncate` 升级为 `discard`，还抑制了过度发散的长篇思维链输出，使 `L1_Easy`、`L2_Medium`、`L3_Hard` 的实际含缓存 API 账单较无 Nudge 分别直降 **`-78.09%`**、**`-52.71%`** 与 **`-21.87%`**；在 `Gemini 4`（`$0.10 / $2.00 / $10.00` per 1M）的 `L3_Hard` 任务上，启用 OSWYN Nudge 比无压缩基线实际含缓存 API 账单净省 **`-22.16%`**（无缓存账单净省 **`-36.26%`**）。

#### 二、实测揭示的客观不足与适用边界（Empirical Limitations）

1. **不足一：在超短会话（$\le 4$ 步）或极高缓存折扣模型（如 `ds4.1f` 98% 缓存折扣，`P_hit : P_out = 1 : 200`）的纯缓存命中短任务上，存在“额外输出费用倒挂”**：
   - **数据证据**：按照 `dsh-cost-meter` 核对的实际官方价格，`DeepSeek 4.1 Flash` 的缓存命中单价仅为 **`¥0.02 / 1M`（`$0.003 / 1M`）**，而输出单价为 **`¥4.00 / 1M`（`$0.60 / 1M`）**——即 **1 个额外输出 Token 的价格等于 200 个缓存命中输入 Token**（在 `Gemini 4` 上为 **100 倍**，在 `Gemini 3.8 Flash` 与 `Kimi 3.1 Pro` 上为 **50 倍**）。
   - 因此，在 **Exp 1 的 15 步连续会话**中，尽管 `OSWYN-Standard` 与 `OSWYN-PTC` 大幅削减了 **`-53.22%`（`-83,584` tok）** 的缓存命中输入和 **`-5.20%`（`-2,210` tok）** 的未缓存全价输入（并在无缓存 API 计费下净省 **`-28.10%` / `-27.79%`**，在 50% 缓存命中交互调试下净省 **`-18.48%` / `-21.40%`**），但如果 15 步全程在几秒内连续跑完且享受 `ds4.1f` 极限的 `¥0.02/M` 缓存命中价，省下的 `83,584` 个缓存命中 Token 仅折合 `¥0.00167`，不足以抵消多生成的 `+3,179 ~ +5,140` 个输出 Token（折合 `¥0.0127 ~ ¥0.0206`），导致 `ds4.1f` 连续极限缓存账单微增 **`+11.99%`（PTC，多约 0.9 分钱）** 至 **`+21.32%`（Standard，多约 1.6 分钱）**。

## 2. 系统架构与形式化成本模型（System Architecture & Formal Cost Model）

### 2.1 基于 `@deepseek-ai/dsh-session` 表面有向无环图（Surface DAG）的原位改写与无损回溯

`dsh-oswyn` 直接运行于 `@deepseek-ai/dsh-session` 内核之上（核心实现见 [`index.js`](file:///Users/reno/Documents/deepseek-harness/default-workspace/dsh-oswyn/index.js) 与 [`lib/core/primitives.js`](file:///Users/reno/Documents/deepseek-harness/default-workspace/dsh-oswyn/lib/core/primitives.js)）。内核采用**追加式不可变事件日志（Append-Only Event Log）**与**可变活跃表面视图（Active Surface Projection）**分离的双层架构：
1. **不可变事件日志与 `tool_result_recall` 闭环**：所有原始 `user/message`、`assistant/message`、`tool/call`、`tool/ptc-dispatch` 与 `tool/result` 事件均以单调递增序号 `seq` 永久保留在底层事件流中。当后续步骤遇到“延迟绑定细节（Late-Bound Details）”时，智能体可调用 `tool_result_recall(call_id)` 从事件日志中按需无损取回原始未压缩输出。
2. **可变活跃表面节点（`session.surface.nodes`）**：每次构建上行 LLM 消息列表时，`session.deriveMessages()` 仅遍历驻留在活跃表面上的事件序列。当 `dsh-oswyn` 对序号为 $s_{\text{target}}$ 的工具结果或助手回复执行原位微蒸馏时，调用内核原语：

$$\text{append}(\text{type}, \text{payload}, \{ \text{surfaceOp}: \{ \text{op}: \texttt{"replace"}, \text{startSeq}: s_{\text{target}}, \text{endSeq}: s_{\text{target}} \} \})$$

该操作在 $\mathcal{O}(1)$ 时间内将活跃表面节点 $s_{\text{target}}$ 替换为精简事件，且**严格保持 $s < s_{\text{target}}$ 的所有历史字节前缀 100% 不变**。

### 2.2 压缩（Compress）与丢弃（Discard）的正交解耦与净收益门控不变量

`dsh-oswyn` 在 [`lib/core/primitives.js`](file:///Users/reno/Documents/deepseek-harness/default-workspace/dsh-oswyn/lib/core/primitives.js) 中定义了两类正交原语：
1. **压缩原语（Compress：仅替换输出，保留入参）**：
   - 包含 **`truncate keep <N> lines|chars`**（前缀保留截断：从字节 0 原样保留前 $N$ 行或前 $N$ 字符，尾部追加紧凑摘要，**100% 保护该节点自身的 KV-Cache 前缀**）与 **`replace`**（全量结构化事实替换）。
   - **核算不变量與净收益门控**：$\text{before}_{\text{compress}} = L_{\text{output}}, \text{after}_{\text{compress}} = L_{\text{distilled\_output}}$。内核强制要求 $\text{after}_{\text{compress}} < \text{before}_{\text{compress}}$，且对主动 `replace` 强制要求摘要长度 $L_{\text{summary}} < 0.30 \times L_{\text{output}}$（否则拒绝并返回 `replace not worth it`）。
2. **丢弃原语（Discard：同时清除入参与输出）**：
   - 包含 **`discard`**（单步废弃）、**`discard entire-ptc`**（整包 PTC 废弃）与 **`cascade`**（连续失败区间废弃），专用于失败调用（`isError = true`）或一次性探测脚本。除将 `tool/result` 替换为 1 行错误根因标记外，`markCallArgDiscarded(session, callId)` 同步将投影中的 `tool-call.arguments` 覆写为空对象 `'{}'`：

   $$\text{before}_{\text{discard}} = L_{\text{input}} + L_{\text{output}}, \quad \text{after}_{\text{discard}} = L_{\text{marker}}, \quad \Delta_{\text{discard}} = (L_{\text{input}} + L_{\text{output}}) - L_{\text{marker}}$$

3. **OSWYN v2.1 能力边界三重防护机制**：
   - **规则 1（Formula-Safe Verbatim Rule，[`lib/prompts/base.js`](file:///Users/reno/Documents/deepseek-harness/default-workspace/dsh-oswyn/lib/prompts/base.js)）**：对源码读取执行 `replace` 时，强制要求逐字原样保留算术公式、除数（如 `Math.floor(x / 250)`）、位掩码（`^`, `&`, `<<`）、条件分支阈值及字面量类型标注（如字符串 `"19"` vs 数字 `19`），严禁将算式概括为自然语言描述。
   - **规则 2（Proactive Recall Gate，[`lib/prompts/nudge.js`](file:///Users/reno/Documents/deepseek-harness/default-workspace/dsh-oswyn/lib/prompts/nudge.js)）**：当后续步骤需要引用前序被 `truncate`/`replace` 折叠的函数实现或表格槽位时，强制要求先调用 `tool_result_recall(call_id)` 取回原文，严禁凭记忆猜算。
   - **规则 3（Final-Turn Reasoning-First Exemption，`isFinalSynthesis`）**：在无需继续调用工具的最终合成/求解轮次，豁免 `dsh-result-summary` 与 `dsh-reply-summary` 围栏输出义务，既把 100% 输出注意力集中在最终计算上，又直接省去最后一轮无后续复利价值的额外输出 Token 费用。

### 4.2 五路架构实测性能与 `DeepSeek 4.1 Flash` 实际 API 价格核算总表

   - 反观 `OSWYN-Standard` 与 `OSWYN-PTC`，由于严格保护历史前缀，15 步累计 `Fresh Tokens` 反而比不压缩基线减少了 **`-5.20%`（`40,297` vs `42,507`）** 与 **`-4.30%`（`40,679` vs `42,507`）**！
2. **为什么在 `DeepSeek 4.1 Flash` 极限连续缓存（`¥0.02/M`）下 `OSWYN-PTC` 微增 `+11.99%`（约 0.9 分钱），而在交互式 50% 缓存、无缓存以及 `Kimi 3.1 Pro` / `Hunyuan 4` 长程会话中全面净省 `-10% ~ -52%`？**
   - `DeepSeek 4.1 Flash` 的 `cacheHit` 单价（`¥0.02/M`）是全行业最低的极值（仅为 `output = ¥4.00/M` 的 **`1/200`**）。在 15 步连续无停顿脚本压测中，`Baseline` 的 `157,056` 个重复缓存 Token 总共只收了 **`¥0.00314`（0.31 分钱）**！因此即使把这 `157,056` 个缓存 Token 100% 全部砍成 0，最多也只能省下 0.31 分钱；而模型多写 `3,179` 个输出 Token 就要花 `¥0.0127`（1.27 分钱）。

     - 一旦开发者在调试步骤之间审阅代码或思考超过 5 分钟导致部分缓存过期（**指标 II：50% 缓存命中交互模式**），`OSWYN-Standard` 与 `OSWYN-PTC` 在 15 步即净省 **`-17.24%` 与 `-19.83%`**，在 30 步净省 **`-33.99%` 与 `-32.48%`**，在 50 步净省 **`-45.54%` 与 `-40.91%`**！
     - 在跨节点无缓存场景（**指标 III**）下，10 步即净省 **`-18.41%`**，15 步净省 **`-28.10%`**，30 步净省 **`-44.95%`**，50 步净省 **`-52.96%`**！
     - 在缓存折扣为 `10%`（`1:10:50`）或输出倍率较低的旗舰模型（如 `Kimi 3.1 Pro`、`Gemini 3.8 Flash`、`Hunyuan 4`）上，即使全程 100% 连续命中缓存，到 30–50 步时也实现 **`-2.14%` 至 `-10.65%`** 的全缓存净省费！

### 7.3 实验四关键机制验证与跨代际性价比分析

1. **v2.1 插件优化的直接实效（`B6` 与 `B9` 从 `66.7%` 跃升至 `100.0%`）**：
   - 在 `B6_Silent_Checksum_Drift` 中，v2.0 的 `OSWYN_With_Recall` 在第 3 轮因同时输出 `dsh-result-summary` 与 `dsh-reply-summary` 两个围栏分流了心算注意力，将 `(148 + 36 + 19) ^ 317 = 203 ^ 317 = 502` 的异或低位算错为 `498`（`2/3 = 66.7%`）。v2.1 引入 **`isFinalSynthesis` 终局免围栏推理豁免**后，模型在最后一轮专注逐位异或推导，**3/3 轮全部精准算对 `502`（`100.0%`）**！
   - 在 `B9_Implicit_Bug_Noise_Maze` 中，v2.0 因将 Step 1 的 `Math.floor(effectiveSkewMs / 250)` 概括为自然语言而丢失了除数 `250`（`2/3 = 66.7%`）。v2.1 引入 **Formula-Safe Verbatim Rule + Proactive Recall Gate** 后，Trial 1/2 在摘要中原样保留了 `/ 250` 算式，Trial 3 在摘要遗漏时主动调用 `tool_result_recall(call_id="c1")` 找回除数 `250`，**3/3 轮全部精准算对 `676`（`100.0%`）**！
2. **跨代际真实 API 成本对比（`ds4.1f + OSWYN v2.1` 仅需 `Gemini 4` 费用的 `7.1%`）**：
   - 表 7 最后一列揭示了极具价值的工程选型结论：在 `B1`–`B10` 共 10 道高难能力边界题上，经过 v2.1 优化的 `DeepSeek 4.1 Flash + OSWYN` 取得了 **`29/30`（`96.7%`，其中 `B1`–`B9` 为 `27/27 = 100.0%`）** 的准确率，而单题平均实际含缓存 API 费用仅为 **`$0.00171`（`¥0.0114` 谷价 / `¥0.0228` 峰价）**；相比之下，使用前沿旗舰 `Gemini 4` 单题平均实际含缓存 API 费用高达 **`$0.0241`（`¥0.1735`）**。这意味着 **`ds4.1f + OSWYN v2.1` 以不到旗舰模型 `1/14`（节省 `-92.9%` 真实 API 成本）的价格，交付了几乎完全持平的工程推理准确率**！

## 8. 综合讨论：部署决策准则与成本盈亏边界（Discussion & Deployment Guidelines）

综合实验一至实验四的数据，我们给出 `dsh-oswyn` 在生产环境中的四条定量部署准则：

1. **准则一（按步数与载荷规模动态门控，规避短会话“高价输出倒挂”）**：
   - 当会话步数 $T \le 4$ 且单步工具输出 $< 4,000$ 字符时，由于输出单价是缓存命中输入的 $50\times\text{–}200\times$，频繁输出围栏会导致短会话费用微增。建议将短问答/小脚本场景的 `nudgeThresholdChars` 调高至 `2000–4000` 字符，并始终开启 v2.1 的 **`isFinalSynthesis` 终局合成轮免围栏豁免**。
   - 一旦会话步数 $T \ge 12\text{–}15$ 步（Exp 1），或单任务累积载荷 $\ge 18\text{k}$ 字符（Exp 2 `L3_Hard`、Exp 4 `B5`），OSWYN 的复利缩减全面超越额外输出成本，实现总 Token **`-35% ~ -57%`**、实际无缓存 API 费用 **`-20% ~ -53%`**、交互式半缓存 API 费用 **`-17% ~ -45%`** 的净节省。
2. **准则二（常驻开启 v2.1 能力边界三重保护与小文件直留策略）**：
   - 常驻启用 `lib/prompts/base.js` 与 `lib/prompts/nudge.js` 中的 **公式算子逐字保留（Formula-Safe Verbatim Rule）** 与 **`tool_result_recall` 按需回溯**，确保能力边界零智损（`B1`–`B9` `100%`、`B1`–`B10` `96.7%`）。
   - 同时，鉴于 `tool_result_recall` 会触发额外 1 轮 LLM 调用（如 `B7` 费用增加 `+200%`），对于体积较小（`<4,000` 字符）且后续大概率跨步引用的核心源码/查找表，直接保留在活跃表面（Keep Intact）比“先 `replace` 再 `recall`”更省钱。
3. **准则三（实施“模型代际分治”与“后台兜底信息隐藏”）**：
   - **严禁在系统提示词中向模型披露后台自动兜底规则（`P2` 道德风险）**，否则主动压缩率归零且费用暴涨 `+25% ~ +43%`。
   - 对 **`DeepSeek 4.1 Flash`** 采用 `P3` 结构化决策树 + 单步 Nudge + 静默后台兜底；对 **`Gemini 4` / `Kimi 3.1 Pro`** 采用精简版提示词（`P1`/`P4`）可再省 **`-28.8% ~ -31.4%`** 实际含缓存 API 费用；对 **`Hunyuan 4`** 保持单步 Nudge 开启可收敛冗余输出并直降 **`-21.9% ~ -78.1%`** 实际 API 账单。
4. **准则四（单栈独立运行 `dsh-oswyn`，严禁与外部代理压缩混用）**：
   - 切勿将 `dsh-oswyn` 与 `billion-context` 等改写中段历史的外部代理叠加运行，避免双协议干扰与 `+21.01% ~ +35.27%` 的 KV-Cache 缓存击穿税。
